## 1. 一句话产品定义

OpinionSearch V1 是一个面向研究与信息分析人员的、可恢复且证据驱动的公开 Web 事件调查工具。它围绕一个公共服务争议事件，在有限公开材料范围内梳理事实、具体争议、相关方主张、机构回应、执行进展与未知事项，输出可逐条核查并可按需更新的事件分析页面。

V1 的合格交付是“研究人员可以继续审核和使用的调查初稿”。在真实案例与人工验收完成前，不宣称系统能够无需人工复核地稳定产出专业舆情报告。

## 2. 目标用户与核心任务

### 2.1 目标用户

- 需要快速了解一个公开事件的研究人员、信息分析人员或营销研究人员。
- 用户愿意核查关键原文，不把模型结果直接当作事实真值。
- V1 面向本地单用户使用，不包含团队空间、账户、权限和多人协作。

### 2.2 必须完成的用户任务

用户完成一条调查后，应能回答：

1. 事件当前处于什么状态，材料查找到什么时间？
2. 哪些事实可以确认，哪些只是相关方表述或解释？
3. 争议集中在哪些具体措施和受影响主体？
4. 各方提出了什么主张或诉求，依据是什么？
5. 机构回应覆盖了什么，哪些问题仍未回答？
6. 回应、事实问题解决、措施执行和用户满意分别处于什么状态？
7. 哪些事项存在证据分歧、范围内未发现材料或无法判断？
8. 新材料相对旧版本加强、削弱、修订或撤回了什么判断？

报告深度以这些任务的完成质量衡量，不以篇幅、搜索次数、来源数量、页面模块数量或图表数量衡量。

## 3. V1 唯一主工作流

```text
输入事件与关注点
    → 必要时澄清事件身份、地区或时间
    → 形成 3–6 个调查问题和事件侧重点
    → 按问题与证据缺口搜索公开材料
    → 保存正文版本并提取可定位证据
    → 形成事实、归因主张、诉求和回应覆盖判断
    → 审查重要断言与引用
    → 发布 complete / partial / failed / cancelled 之一
    → 在 Web 核查原文与调查限制
    → 用户按需补查新进展
    → 比较报告版本与判断变化
```

V1 的产品验收围绕这条链路进行。不能改善这条链路正确性、报告价值或用户核查效率的功能，不进入 V1。

## 4. 功能边界

### 4.1 支持的事件

首版支持边界清楚、存在公开材料的公共服务争议事件：

- 公共交通服务或规则调整；
- 公共设施服务、收费或补救争议；
- 文旅服务措施与公开回应；
- 其他公共服务规则、执行或纠正事件。

V1 只承诺通过三个真实案例验证有限场景可用，不承诺覆盖所有行业和所有舆情类型。

### 4.2 支持的材料

- 机构公告和公开文件；
- 可公开访问的新闻报道；
- 公开研究材料；
- 有明确作者或机构归属的评论文章；
- 用户提供且属于上述公开范围的参考链接。

每份进入证据链的材料应保存请求 URL、最终 URL、获取时间、可获得的发布或更新时间、不可变正文版本、正文哈希和原文定位。无法确认的日期保持未知。

### 4.3 支持的分析

- 事件事实与时间线；
- 具体争议问题；
- 主体、主张、诉求和针对具体措施的态度；
- 支持与反驳证据；
- 机构回应的逐项覆盖；
- 回应后的执行或落实证据；
- 已确认、存在分歧、范围内未发现和无法判断的事项；
- 新发现旧材料、事件新进展、页面内容变化和版本判断变化。

价值诉求不按真假判定。公开材料中的主张数量不能解释为公众观点比例，除非将来另行建立具有代表性的采样与去重契约。

### 4.4 支持的 Web 产物

- 调查创建、必要澄清、进度、取消和刷新恢复；
- 一个统一可信页面框架，加规则、服务、计费、调查纠正等白名单专项模块；
- 关键判断、时间线、争议与回应、材料关系、证据原文和调查限制；
- 定向补查、历史版本与版本差异；
- 与同一报告版本绑定的 Markdown 和自包含 HTML 下载。

模型不得输出 HTML、CSS、脚本或任意组件名称。PagePlan 只能从已确认事件侧重、调查问题和已提交领域状态确定性生成。

## 5. 正确性与完成契约

### 5.1 判断与引用

- 事实、归因转述、解释和诉求必须分开记录。
- 重要事实性断言必须有可定位原文支持；引用缺失时在对应位置降级或删除。
- 数字、单位、对象、时间、否定和限制条件必须作为完整断言审查。
- 相同正文、转载、转述和引用不能仅因 URL 或域名不同而算作独立验证。
- “机构称已解决”只能作为归因说法，除非存在独立执行证据。

### 5.2 回应覆盖

回应分类固定为：直接回答、部分回答、涉及但未实质回答、范围内未发现可对应回应、无法判断。

以下概念分别判断，不相互替代：

- 回应是否覆盖问题；
- 事实问题是否得到解决；
- 措施是否实际执行；
- 受影响群体是否满意。

“范围内未发现回应”必须带调查截止时间和查找范围。搜索或读取失败时使用“无法判断”。

### 5.3 complete 与 partial

`completed` 只表示当前完成策略满足，不表示结论是真值。完整报告至少满足：

- 每个必答问题和必答子项均有明确处置；
- 回答或分歧判断有证据；
- 当前有效的重要判断经过与当前文本绑定的审查；
- 用户实际问题要求的专项字段已经处理；
- 关键来源关系、时间和读取失败没有被隐去；
- 当前结论能够定位到对应正文版本。

下列情况应发布 partial：

- 关键材料不可得或读取失败；
- 必答问题或子项无法完成；
- 重要判断未通过审查；
- 用户问题真正需要的专项内容仍缺失；
- 预算耗尽时仍有重大未完成事项。

合格的“未知”可以完成一个问题。页面模板中的可选字段为空，不能单独导致整个调查 partial。

## 6. 明确不进入 V1

- 社交平台搜索、采集和账号级数据；
- 全网声量、传播路径、热度榜、情绪比例和代表性公众观点饼图；
- 剧集播出后的自动持续监测、预警和定时报告；
- 自动生成或发布对外回应；
- 多 Agent、subagent 或独立角色编排；
- 多用户、多租户、团队权限和云端协作；
- 分布式队列、调度平台和远端 worker；
- 向量数据库、跨事件知识库和通用 RAG 平台；
- 独立 Observability、Eval、Benchmark 或数据标注平台；
- 任意 HTML 生成、页面编辑器和无限事件模板；
- 前端框架迁移；
- 新 CLI 产品流程；
- PDF、Word 和独立分享发布系统。

已有 CLI 和通用 Runtime 在共享代码变化时维持必要兼容，但不作为 V1 新功能入口。

## 7. V1 验收门槛

首版使用三个真实案例收口：两个开发案例和一个保留验收案例。至少一个案例包含 T0/T1 两个材料时点。通过后只说明有限场景可用。

| 验收项 | V1 通过条件 |
|---|---|
| 必答问题 | 人工检查至少 90% 获得正确回答或恰当未知说明 |
| 重要断言 | 人工检查至少 95% 获得引用支持或正确降级，并公布检查分母 |
| 引用定位 | 结构完整性 100%，全部引用命中对应正文版本的非空原文 |
| 禁止错误 | 归因变事实、转载当独立验证、回应当解决、旧文当新进展的保留用例全部通过 |
| 更新能力 | 至少一次新证据导致有依据的加强、削弱、修订或撤回，旧版本保持不变 |
| Web 主路径 | 实际浏览器完成提交、阅读、证据核查、补查、比较和刷新恢复 |
| 真实链路 | 最新生产代码至少完成一次真实联网调查，保留预算、失败和限制记录 |
| 相对价值 | 同材料、同模型下与简单摘要比较，能指出具体质量改善和额外成本 |

合成案例、测试数量、`completed` 状态、引用 ID 存在和 reviewer 返回 supported 均不能单独证明报告质量达标。

## 8. 实施准入规则

V1 只允许三类新增工作：

1. 修复会造成错引、误归因、时间混淆、错误完成判断或版本污染的正确性问题；
2. 获取和验证真实报告质量证据，包括冻结材料回放、联网发现、人工检查和简单摘要对照；
3. 修复提交、阅读、证据核查、补查、版本比较和刷新恢复中的主路径可用性问题。

每项工作开始前必须回答：

- 它对应哪一个 V1 用户任务或验收门槛？
- 当前有哪个真实案例、失败记录或主路径障碍证明它需要做？
- 完成后用什么有限证据判定通过？
- 是否引入了“不进入 V1”清单中的新系统？

不能回答前三项，或命中第四项的工作，进入 Backlog，不在 V1 实施。

## 9. 停止条件与范围变更

当三个真实案例达到第 7 节门槛、Web 主路径通过、真实链路产物可审计时，V1 停止增加功能，转入文档、演示和发布准备。

针对真实案例最多进行两轮集中质量修复。两轮后仍未达到门槛，应缩小支持场景或将产品标记为实验性调查工具，并记录失败原因，不以继续扩建基础设施替代范围决策。

任何新增能力若涉及持续监测、社交采集、代表性观点比例、多用户、分布式运行或跨事件知识库，都视为 V2 范围变更。变更前必须单独说明目标用户、数据来源、统计口径、预算、风险和验收，不通过修改本文件的措辞静默扩张 V1。

## 10. 当前项目位置

截至本文件生效时：调查 Runtime、公开 Web 搜索与阅读、正文版本、证据定位、问题与回应建模、审查、checkpoint、更新、PagePlan、工作台、HTML/Markdown 导出和链路诊断已有实现及合成材料机制验证。

当前决定 V1 是否完成的主要缺口是：最新生产链路的真实模型报告、三个真实案例的人工评分、与简单摘要的同条件对照，以及真实联网发现能力的有限验收。后续优先投入这些证据；新机制只有在真实失败能够定位到现有契约不足时才进入实现。
