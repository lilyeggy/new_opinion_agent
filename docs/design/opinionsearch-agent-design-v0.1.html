舆情搜索 Agent 设计总览 （多角色提案，已否决）

给定一个具体舆情事件，搜索公开材料，产出结构化、可追溯、可审查的 HTML 式报告。内容由 Agent 与 Harness 负责，渲染由 Presentation Contract 负责；两者分离。

状态：已否决（2026-09-21）· 2026-09-24 按代码校正
本页描述的分层多角色架构（Controller / Research Agent / Analyst / Reviewer，以及 Legal Action Kernel / Scheduler / ResourceLedger / GapAudit）是 2026-09-16 的提案，已实现为独立实验并评估后归档至 opinion_search_agent/archive/harness-pipeline/，不是当前系统。否决理由：① 违反单 Runtime 原则——该流水线是与 Runtime 零共享代码的第二个 loop；② 与生产路径能力重复且更弱——「整体骨架 → 定向搜索」已由 PagePlan + search_targets 实现；③ 工程质量差距无法低成本补齐。决策记录见归档 README。当前实现是唯一 Runtime AgentLoop + 两套领域组合（domain/opinion / domain/investigation）。本页的 Report Contract、ModuleContract、空值与图表等渲染契约部分仍然有效。
核心判断：不是固定 workflow，也不是自由多 Agent 群，而是有硬边界的 Agent 自主决策循环。LLM 只做局部语义判断；全局、确定、可验证的事情归 Harness。

2. 内容 vs 渲染

Content Contract · 主 Agent 负责

EventIssueActorPositionResponseSourceEvidenceFindingReview

定义有什么信息、依赖什么、能否发布。事实性内容必须可追溯到 Evidence 和 Review。

Presentation Contract · 表现层负责

cardstimelinecomparison-tableposition-matrixrelation-graphdistribution-charttrend-chartevidence-drawer

定义如何表现、如何交互、缺失时如何显示。图表数据只能由程序从结构化状态生成。

渲染 LLM 策略：MVP 不把渲染 LLM 放进主框架。主 Harness 产出结构化内容，Renderer 确定性生成 HTML。未来如需更强版式能力，可增加独立的 PresentationPlanner，只输出 PresentationPlan JSON，不生成 HTML/CSS/JS，不修改 Finding/Evidence/Review。

3. Agent 角色

Controller / Lead

决定全局下一步：Plan / DispatchResearch / Analyze / Review / ReviseStrategy / Finish。

无搜索工具宏观决策

Research Agent

唯一拥有 Search / Read / Retrieve 的角色，在局部任务内自主搜索并返回 EvidencePacket。

唯一 AgentLoop局部自主

Analyst

只处理冻结证据，形成原子 Finding、Issue 处置、有界叙述和模块字段提案。

无互联网工具证据分析

Reviewer

独立核查 Finding 和事实性叙述：support / partial / contradicted / insufficient。

强制门禁版本绑定

4. Harness 程序服务

Legal Action Kernel

根据当前状态计算 Controller 的合法动作空间，不替 Controller 选择动作。

Scheduler / Coverage

计算 Issue、来源角色、模块字段、Review 补查的优先级，为 Controller 提供建议。

ResourceLedger

统一管理搜索、读取、各角色调用、时间和 publication reserve。

GapAudit

判断继续、深化、策略修订或收束；只读状态，不产生新事实。

Validator / Reducer

所有 Proposal 必须经过校验、Delta、Reducer 才能提交为权威状态。

Finalizer / PageProjector

从 reviewed state 和 Presentation Contract 确定性投影 HTML。

6. Report Contract

内容实体

Event Issue / Component Actor Statement / Position / Demand Response Source / SourceVersion / SourceRelation Evidence Finding / Review Module / Metric

内容关系

  • Event 是根，Issue 是调查维度。
  • Actor 产生 Statement / Position / Demand。
  • Response 指向具体 Issue。
  • Evidence 是最小可追溯事实单元。
  • Finding 是 Issue 级 reviewed 判断。
  • SourceRelation 影响来源独立性。
  • Module 只做投影，不产生新事实。

8. 空值与图表

空值状态

not_applicable 本事件不适用not_found 搜索后范围内没有insufficient 找到但不足以支持结论unavailable 供应商失败或来源不可访问pending 尚未调查omitted 可选模块无内容，直接省略

空值不是失败。页面应区分不适用、没找到、证据不足、失败和还没查。

视觉编码

textcardstimelinecomparison-tableposition-matrixrelation-graphdistribution-charttrend-chartevidence-drawer

图表由程序从结构化状态生成。没有有效分母，不画比例图；公开网页样本不推断全网热度或公众情感比例。

11. 实施边界

  1. Phase 1 · Content Contract + Domain State
  2. Phase 2 · 确定性 PageProjector

  4. Phase 4 · Research Agent + EvidencePacket
  5. Phase 5 · Analyst + Reviewer + 强制 Review
  6. Phase 6 · 端到端验收与空值 / Partial / 失败回放

下午需要冻结的 10 条边界

  • 渲染 LLM 首版不进主框架，先做确定性 Renderer。
  • Content Contract 与 Presentation Contract 分离。
  • ModuleContract 按本页定义。
  • 空值状态采用 not_applicable / not_found / insufficient / unavailable / pending / omitted。
  • LLM 角色采用 Controller / ResearchAgent / Analyst / Reviewer。
  • Controller Agent 自主选择合法动作，不做固定 workflow。
  • 所有 Agent 只能提交 Proposal，Global Domain State 单写者。
  • 首版全局 Checkpoint 唯一权威。
  • 图表由程序生成，无有效分母不画比例图。
  • 首版不引入社交平台数据源，相关模块标 unavailable。
