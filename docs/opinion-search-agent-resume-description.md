## 简历投递版（推荐）

### OpinionSearch｜基于证据的智能舆情调研 Agent

**个人项目｜核心开发｜2026.08–至今**  
**技术栈：** Python、asyncio、Pydantic、HTTPX、MCP、SSE、Pytest

- 独立完成舆情调研 Agent 的端到端闭环：用户输入议题、时间范围和关注方向后，Agent 可自主执行搜索、网页阅读、证据整理与补充调查，最终生成包含**事实脉络、相关方立场、主要/反方叙事、争议点及引用来源**的结构化报告；提供 Web 控制台实时展示调查进度，并支持任务取消和结果下载。
- 针对长任务中模型超时、工具失败和进程中断问题，自研可恢复的异步 Agent 执行引擎，将一次推理拆分为“决策—工具执行—结果记录—状态提交”四个阶段，通过原子 Checkpoint 与工具结果持久化实现断点续跑，避免恢复后重复调用工具或重复写入调查状态。
- 设计统一工具接入层，完成 Brave Search、Jina Reader 与 MCP 工具集成，并统一处理参数校验、超时重试、服务降级、熔断和缓存；通过有界上下文与证据溯源机制控制长程调查的上下文增长，隔离网页 Prompt Injection。以故障注入、恢复场景和 Web E2E 为核心建立 **570+ 自动化测试**，并完成真实模型与真实搜索/阅读服务的全链路验证。

## 30 秒项目口述

这个项目解决的是：普通搜索只能给链接，通用大模型又容易遗漏来源或产生无依据结论。我做了一个舆情调研 Agent，让它围绕一个议题自主搜索和阅读网页，再按事实、相关方立场、主流与反方叙事组织证据，输出每条结论都能追溯来源的报告。工程上最难的是长任务的可靠性，所以我没有直接套 Agent 框架，而是自己实现了带 Checkpoint 的异步执行流程，并统一处理工具重试、降级和上下文预算。目前项目跑通过真实模型和真实搜索链路，并用 570+ 自动化测试覆盖关键失败场景。

## 面试表述边界

- 使用“可恢复”“已成功结果可复用”“领域状态至多提交一次”，不声称通用 exactly-once。
- 使用“公开网页样本中的观点与叙事”，不声称完成全网舆情监测或精确情感占比。
- 使用“独立实现核心 Harness 语义，并借助 AI 完成部分机械代码与测试”，不回避 AI 辅助开发，也不把未亲自掌握的实现写进简历。
