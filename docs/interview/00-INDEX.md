# OpinionSearch Agent Harness 面试资料集

> 用途：拿这个项目去面试时，一套可以反复读、反复背、反复自测的完整材料。
> 唯一事实源：`opinion_search_agent/src/` 的代码。所有断言都能在代码里找到落点，或标注为"实测数字/人工检验"。
> 最后校准：2026-09-25（对照 `src/` 全量重读）。

## 这套材料解决什么问题

面试这个项目时，真正的难点不是"记不住架构"，而是三件事：

1. **讲不出边界**——面试官问"你为什么不做 X"，答不上来就显得是没想到而不是不想做。
2. **讲不准细节**——"十个协议接口""两套 domain 共用 Context Compiler"这类说法听起来顺，被追问一句就穿。
3. **讲不出证据**——只有设计没有数字和失败故事，说服力会掉一个档次。

这套材料按这三件事组织：`01/02` 解决边界与整体，`03` 解决细节准确度，`04–06` 解决取舍与证据，`07/08/09` 是临场工具。

## 三条使用纪律

1. **一切以代码为准。** 本套材料里凡是写"代码落点"的地方，符号名都经过核对；若你改了代码，先回来改这里。
2. **数字要带口径。** 说"788 passed"要能说清是哪套命令、哪个目录、什么环境（沙箱里还有 3 个时序失败）；说"召回率 60%"要能说清是 6/10 人工标注必中项。`05` 里每个数字都标了口径。
3. **不说的比说的更重要。** `08` 列出的每一条都是"与代码不符"的说法。宁可少说一句，不要说错一句。

## 一分钟版本（如果只有一分钟准备）

> 这是一个面向公开 Web 舆情调查的**可恢复单 Agent Harness**。模型每轮只提一个 `search / read / reflect / finish` 决策；Runtime 把它校验、解析成动作、执行、拿到 Observation，再由领域处理器构造 Delta，经**纯函数 Reducer** 提交成新的权威 State，每个阶段边界都落 checkpoint。所以"首次执行"和"崩溃恢复"走的是同一条代码路径。
>
> 我刻意只深做两层：Harness/Runtime，和 Tool/MCP/Context/Run-scoped Memory。不做多 Agent、不做 LangGraph、不做 Eval 平台——多 Agent 那条线我实现过，评估后砍掉并归档了。
>
> 验证上：正常环境全量 779 passed / 2 skipped（受限沙箱重跑 788 passed / 3 failed / 2 skipped，3 个失败是轮询终态的时限断言被拖慢）；一次真实 live run 跑满 60 步、17 搜 / 17 读 / 14 findings / 92 引用；100 步 / 640 条证据的长轨迹压力测试；14 路 prompt injection 矩阵；三个崩溃窗口的恢复矩阵。

（精确数字与口径见 `05`，开场稿的完整版本见 `01`。）
