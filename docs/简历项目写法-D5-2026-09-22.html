简历项目写法：舆情搜索 Agent（技术核心：Agent Harness 构建）

2026-09-22 · 秋招 · Agent 构建开发方向 · 所有数字与代码/测试/报告一一对应，可承受追问

一、定位：产品是舆情搜索 agent，壁垒是 harness 工程

这个项目在简历上就是一个「舆情搜索 agent」——输入一个舆情事件，它自主完成多轮搜索、阅读、反思、审查，产出一份每条结论都带证据引用的调查报告。这是面试官第一眼要看到的画面，清晰、具体、有真实场景。

但「舆情搜索 agent」这个品类满地都是 demo：prompt + 搜索 API + 总结，三天能拼一个。所以这个项目的简历叙事必须马上回答下一个问题——「你这个和 tutorial 项目有什么区别？」答案就是技术核心：它的可信度不是来自 prompt 技巧，而是来自底层自研的 Agent Harness——状态事务、崩溃恢复、工具信任边界、上下文工程。舆情只是恰好最能暴露这些机制价值的场景（任务长、外部工具抖、网页内容不可信、结论必须可核查）。

一句话结构：「舆情搜索 agent 让人有画面，harness 让面试官有题可问，数字让答案有据可查。」三条纪律：

  • 第一条 bullet 讲产品与结果（它做什么、跑出了什么），后三条讲技术核心（它是怎么被造得可信的）。顺序不能反——先给画面再给机制。
  • 数字分两类别混。机制数字（779 测试、100 步/640 证据恢复一致、18 次闸门拒绝）上简历；质量数字（召回 60%）留作面试主动讲，「知道短板在哪」比「声称领先」更打动人。
  • 不夸大终态。live 终态是诚实 partial，别写「自动生成高质量舆情报告」这种会被当场戳穿的话。

二、推荐版（4 条 bullet，主投 Agent/AI 工程岗）

舆情搜索 Agent —— 面向公开事件的自主调查系统（技术核心：自研 Agent Harness）
个人项目 · 2026.08–2026.09 · Python asyncio / 自研 Agent Loop / OpenAI-compatible LLM / Brave Search / Jina Reader · 779 项自动化测试
  • 实现端到端舆情调查流程：输入舆情事件与必答问题，Agent 自主执行「多轮搜索 → 正文阅读 → 反思补缺 → 交叉审查 → 发布」全流程，产出每条结论均带证据字符级定位的调查报告；真实中文事件 live 闭环 60 步 / 17 次搜索 / 14 条 finding / 92 处证据引用，完成闸门拒绝 finish 18 次直至证据闭环——宁可输出 partial 也不强行收尾。
  • 技术核心：设计并实现显式 Agent Runtime。定义 Decision→Action→Observation→Delta 协议与 Processor→Delta→Reducer 纯函数事务，Loop 仅管理时序、Reducer 独占状态写入权；相位级 checkpoint/resume 在「工具成功但状态提交前崩溃」时按 action identity 复用持久化结果，实现 state effect 的 effectively-once——100 步 / 640 条证据压力测试下恢复后模型上下文逐字节一致。
  • 构建工具运行时与上下文工程两层基础设施：ToolExecutor 提供有界重试、跨 provider 熔断 fallback、成功缓存，MCP 收敛为不可信 Tool adapter（schema 哈希契约校验、元数据递归剥离、强制 HTTPS）；分层 Context Compiler 以 required window + 可丢弃 chunks 控制上下文规模不随 run 增长，内容来源信任标记全程不洗白，14 条路径 prompt 注入对抗矩阵进入 CI。
  • 建立舆情报告质量验收方法：人工标注「必中清单」度量检索召回，逐条核对 finding 与证据的忠实性（零虚构），在冻结材料中埋入更正/反方/错误数字三类对抗点做真实模型 replay；曾用九阶段诊断链定位并修复「44 条证据 0 finding」级缺陷，形成「失败 → 诊断 → 修复 → 复跑」的完整工程闭环。

结构逻辑：第 1 条 = 这是什么（产品+结果）；第 2、3 条 = 为什么可信（技术核心 harness）；第 4 条 = 我怎么知道它work（验收工程）。对应面试节奏：demo 画面 → 机制深挖 → 工程素养。

四、英文版（外企/海外岗）

Opinion Search Agent — Autonomous Investigation over the Public Web
Personal Project · Aug–Sep 2026 · Python asyncio / Custom Agent Loop / OpenAI-compatible LLM / Brave Search / Jina Reader · 779 automated tests
  • Built an end-to-end opinion-investigation agent: given a public event and required questions, it autonomously runs multi-round search → read → reflect → review → publish, producing a report where every finding carries character-level evidence locators. A real Chinese event completed a 60-step live run (17 searches, 14 findings, 92 evidence citations); the completion gate rejected finish 18 times rather than close with unanswered questions.
  • Technical core: designed an explicit agent runtime — Decision→Action→Observation→Delta protocol, Processor→Delta→Reducer pure-function transactions (loop owns sequencing, reducer exclusively owns state). Phase-level checkpoint/resume with an action-identity success cache achieves effectively-once state effects: byte-identical context after resume in a 100-step / 640-evidence stress test.
  • Built the tool runtime and context layer: bounded retry, cross-provider fallback with circuit breaking, success caching; MCP reduced to an untrusted adapter (schema-hash pinning, metadata stripping, HTTPS-only). A layered context compiler (bounded window + droppable chunks, provenance tags with SHA-256) keeps required context from growing with the run; a 14-path prompt-injection matrix runs in CI.
  • Established quality baselines for opinion reports: human-labeled must-hit recall, per-finding faithfulness checks (zero fabrication), and adversarial replay with planted corrections / counter-narratives / wrong numbers; diagnosed and fixed a "44 evidence, 0 findings" failure via a nine-phase diagnostic chain.

五、写法对照：为什么这样写

别这么写这么写原因
调用搜索 API 和大模型 API 实现舆情信息聚合与总结自主执行「搜索→阅读→反思→审查→发布」全流程，结论逐条带证据字符级定位调 API 是拼装；闭环流程 + 证据可核查才是系统
使用 LangChain/AutoGen 搭建多智能体协作流程自研单 Agent async loop（决策记录：为什么不用框架）用了框架，Runtime 深度就不是你的；「为什么不用 LangGraph」是你的送分题
实现了断点续传功能相位级 checkpoint/resume；工具成功未提交时按 action identity 复用，effectively-once「断点续传」人人会写；相位分类 + 恰好一次语义是分布式系统语言
系统稳定可靠，报告准确率高779 项测试；100 步/640 证据恢复后上下文逐字节一致；忠实性零虚构形容词无价值；可复核的断言才值钱
报告质量达到行业领先水平（简历不写质量形容词；面试主动讲召回 60% 与短板定位）质量是相对的容易被戳；知道短板在哪比声称领先更打动人

七、放置与搭配建议

  • 位置：项目经历第一条。它是你唯一一个「有完整产品形态 + Runtime 深度 + 真实验证 + 质量数字」的项目，必须吃第一眼的注意力。
  • 技术栈行：别列「Python, Git, Linux」占位符，列有信息量的：Python asyncio / 自研 Agent Loop / OpenAI-compatible LLM / Brave Search / Jina Reader / MCP SDK v2 / pytest（779 项）。
  • 技能栏呼应：「LLM 应用开发」改成「Agent 系统设计与构建（Runtime / 工具运行时 / 上下文工程）」——简历通篇用同一套词汇，面试官的关键词会自己匹配上。
  • 自我介绍钩子：「我做了一个舆情搜索 agent——给它一个事件，它自己搜、自己读、自己查证，最后交出一份每条结论都能点开看原文出处的报告。技术上最有意思的部分是底层自研的 agent harness：怎么让跑几十步的 agent 挂了能恢复、读到假网页不中毒、证据不足时宁可说不知道。」——三句话，画面、核心、价值观各一句，让面试官自己选从哪句挖。
  • 投递变体：投偏产品/应用的岗，把第 1 条和第 4 条（产品与验收）展开、压缩第 3 条；投偏 infra/平台的岗，把第 2、3 条展开。四条 bullet 的组合不用动，只调详略。
