# OpinionSearch 产品契约与实施决策草案

> 状态：讨论草案；已确认产品方向与待决事项分别标记。本文不修改现有代码，不宣称目标能力已经实现，也不自动替代现有 canonical design 和 V1 边界文档。当前仓库中旧 V1 文档以公共服务事件为主，用户已澄清产品面向广义舆情事件，不限定中文品牌或广告争议；品牌案例只是可选的评测案例。具体支持的事件边界仍需讨论；待产品与实施决策经用户审阅后，再明确正式文档的调整。
>
> 协作方式：用户参与全部重大产品、评测和架构决策。每个决策先说明问题、候选方案、取舍、证据和可验证后果；用户作出选择后记录原因，再决定是否实施。AI 可以准备材料、对照代码和执行已获授权的工作，不能将自己的建议写成用户已经决定的事实。

## 1. 项目背景与目的

项目最初面向广告营销公司，希望监测社交平台舆情并汇总报告。由于平台数据获取没有解决，且这不是当前项目希望深做的方向，产品调整为对用户给定事件进行公开网页调查。原合作已经结束：营销人员是模拟目标用户，并无现有公司用户或实际业务反馈可作为验收依据。

项目有两条相互关联的目标：

1. 产品：为用户给定的舆情事件生成供人核查的调查初稿；具体支持范围仍需共同确定。
2. 学习与工程：亲自理解并参与关键决策，解释问题、选型、替代方案、失败边界与验证证据；建立评测驱动的改进闭环。

## 2. 已确认的产品范围

| 事项 | 已确认的选择 | 边界 |
|---|---|---|
| 产品类型 | 用户给定事件，按需开展公开事件调查 | 不承诺实时、持续监测或自动发现事件 |
| 目标用户 | 模拟广告营销公司内部员工，阅读与核查报告并决定如何使用 | 目前没有真实合作方或用户，不能宣称解决了实际业务问题 |
| 事件类型 | 面向广义舆情事件，不限定品牌、广告或中文事件 | 具体支持范围与测试分布待共同确定；不能据此承诺支持所有事件 |
| 输入 | 用户输入一句自然语言即可 | 不要求用户预先填写固定表单 |
| 澄清 | 信息不明确时由 LLM 参与判断；若少量搜索可能消歧，先搜索；仍无法区分时追问 | 少量搜索后仍有多个可能事件时暂停并请用户选择，未回答时保持等待；消歧搜索工具不可用时说明失败并请用户补充，仍无法确认则等待。搜索量、轮数和重试策略待定 |
| 来源 | 调查可以公开获取的网页材料 | 可公开获取的社交内容可纳入，但不保证覆盖特定平台；不承担平台爬虫和实时采集承诺 |
| 报告目的 | 快速了解经过、争议、各方观点、相关主体回应、依据与未知事项 | 不自动生成业务决策或保证报告无需人工复核 |
| 原始公告 | 没有原始公告也可以交付 | 必须准确说明来源及归属；媒体转述不得写成已经看到品牌公告 |
| 证据展示 | 每个重要事实或观点应显示来源链接和相关原文摘录，标明说话主体 | 摘录和来源应支持对应表述；搜索结果提到重要信息但原文无法读取时，不作为已核实事实，可列为待核查线索并说明原因。已读来源后续链接失效时，允许查看保存的摘录，标明读取时间及原链接不可用 |
| 信息不足 | 可以交付部分报告，明确未知、调查范围与限制 | 未找到不等于不存在；不能编造或隐去缺口 |
| 错误停止后交付 | 模型或工具错误导致调查提前停止时，若已有可核查内容，展示部分报告 | 明确说明因错误提前停止、停止原因和未完成内容；不把部分结果表述为正常完成 |
| 更新与对比 | 先证明一次调查与报告，补查、版本比较暂非 V1 必需能力 | 不等于立即删除现有实现，是否保留需另行决策 |
| 价值验证 | 评测属于交付闭环；先由我们亲自标注一批案例、测出基线，再共同确定具体量化门槛 | 自己标注或模拟试用可以评估案例表现，但不能证明真实用户收益；案例规模与标注方法待定 |

## 3. 一次调查的产品契约

用户输入一句话后，系统应尽力识别目标事件和用户想了解的问题。必要时先进行有界的轻量搜索以区分对象；如果仍无法区分多个可能事件，就暂停调查并请用户选择；用户未回答时保持等待。消歧搜索工具暂时不可用时说明失败并请用户补充信息；仍不能确认事件时保持等待，不能将工具失败当作事件不存在。用户回答后，在明确的事件范围内调查并形成报告。

报告至少应能交代：事件经过、具体争议、材料中涉及的各方观点、相关主体回应、来源与可核查依据、未解决问题及调查范围。品牌回应是涉及品牌事件时的一个例子。没有材料支持的项目应显示未知或说明未覆盖，而不是为了凑齐章节写成结论。不同形式的页面或导出应针对同一调查结果和版本，具体实现尚未决策。

最低安全语义：

- 区分事实、主体观点、媒体转述、推测和未确认事项；具体标注粒度待评测样例确定。
- 每个重要事实或观点应显示来源链接和相关原文摘录，并标明是谁的说法；引用存在并不自动证明它支持判断。已读取的来源在之后链接失效时，允许查看调查时保存的摘录，标明读取时间及原链接不可用；链接状态应反映检查时间，检查失败时标记无法确认，不推断不可用。
- 如果材料仅转述某人发言，报告不能声称直接核实了原始发言或公告。
- 搜索结果提到重要信息但网页无法读取原文时，不得写成已核实事实；可列为待核查线索，注明原文无法访问。
- 页面、报告或模型的格式要求不能自行扩大用户的调查问题。
- 不根据检索结果数量推断公众情绪比例、平台覆盖率或观点代表性。
- 无论结果完整与否，应让阅读者知道主要未解决事项和本次调查范围。

这是一组目标要求，不是对现有实现效果的认证。

## 4. 运行和结果的语义（建议，待决定）

建议将两个问题分开表达：

- 执行：正常结束、异常停止、用户取消等；
- 覆盖：核心问题已回答、部分回答、无法判断等。

原因：调查按计划结束但证据不足，和调查因模型错误提前停止，都可能生成部分报告，却对用户有不同含义。现有实现存在 partial 状态，最近一次真实运行因决策恢复耗尽而 partial；如何映射旧状态和如何在页面展示仍待用户确认。

已决定：模型或工具错误导致调查提前停止时，若已有可核查内容，展示部分报告，并明确说明停止原因和未完成内容。这样既保留已有调查价值，又不让阅读者误认为调查正常完成。

未决定：何时可以称为完整、无可核查材料时如何展示、取消后如何展示，以及具体状态字段和页面文案。未有证据前不设具体通过比例。

## 5. 初始评测设计（提案，非评测成绩）

已决定：先由我们亲自标注一批案例并测出基线，再共同决定具体量化门槛。基线是观察结果而非合格证明；调查错事件、无依据内容被写成事实等重大错误应单独记录和讨论，不等待通过率阈值才重视。首条案例由助手整理来源和候选标注，用户逐项判断并修改；在用户审阅之前不运行 Agent。案例初版数量与时间成本需共同决定，不把建议数量写成合格门槛。材料采用可追溯的冻结版本用于回归，另设按需联网运行，分别解释能力、成本和外部环境变化的影响。搜索和阅读结果只有在冻结材料、时间范围及判定规则明确时才可作为该案例的有限参考，不声称穷尽互联网事实。

每个案例建议包含：用户输入；目标事件；是否存在歧义及合理的追问/可接受行为；有限材料范围与来源；必要问题及可接受的有证据答案；未知项、常见错误与人工标注理由。标注时可用多个合理输出或人工评分，避免只依赖唯一标准答案。

评测维度：

| 维度 | 验证问题 | 初始方法 |
|---|---|---|
| 输入与澄清 | 是否识别正确事件；该问时问、不该问时不过度打断 | 人工标注典型输入并检查提问和接受的范围 |
| 发现与阅读 | 在限定参考材料范围内能否找到并读到关键内容 | 分开记录发现、成功读取和未读原因；不以候选命中替代已读 |
| 证据与归属 | 关键判断是否有支持、正确指明说话者 | 自动检查引用定位，人工检查语义支持和来源归属 |
| 报告覆盖和不确定性 | 是否回答用户问题；冲突、未知与限制是否明确 | 人工按案例标准评审，记录遗漏与过度断言 |
| 执行与成本 | 是否正常结束，失败能否解释，耗时和调用代价 | 记录终态、失败原因、阶段耗时和可获得的费用；未知费用标记未知 |
| 人员价值 | 是否有助员工完成工作 | 当前无真实用户，不能声称已证明；用户自己模拟任务只能作为探索性观察 |

人评为主要依据，自动规则检查可定位的结构与机制；LLM 评审可以探索但必须与人工标注校准。记录个案、分母、样本组成、标注者、运行环境和失败类别；不从单个案例、单次运行或少量样本推断普遍成功率。

现有 `opinion_search_agent/evaluation/README.md` 有冻结运行、人工标注和离线门禁，可先审计再决定复用；它是有限冻结数据可重算的证据，不等同于新产品契约的完整验收。原始产物、标注归属、旧 opinion 案例可用性及数据许可需要核对。现有用户资产和已修改工作区需保留，禁止为测试而覆盖。

## 6. 系统设计与技术选型：尚未冻结

当前可确认：仓库有 investigation 产品路径、单 Agent Runtime、工具、页面、部分澄清/恢复及离线评测。具体可用性和本契约符合程度须逐项核对，不以文档或一次运行替代验证。

以下均是要比较的决策，不是预定实现：

1. **工作流**：用户初步选择固定主流程、每一步由 LLM 判断具体调查动作；阶段划分、合法动作、跳转和 LLM/系统权限仍需共同设计，不等同于固定搜索顺序或已经决定多 Agent。在现有单 Agent 上改进还是拆分角色，仍需以失败证据、成本和复杂度比较。
2. **检索与上下文**：先检查搜索、已读材料和证据召回问题，再比较全文检索、向量检索、重排等；不默认 Embedding 或 Rerank 必需。
3. **澄清策略**：何时进行少量搜索、何时追问、搜索和追问预算、用户不回答及外部工具故障如何处理。
4. **结果与页面**：一份调查结果的权威来源、交互页面和导出的职责，以及生成失败如何处理。
5. **执行与覆盖状态**：哪些条件对应正常结束、部分结果、失败与取消，用户看到什么；旧状态兼容如何处理。
6. **审查和护栏**：哪些是机器可强制的结构检查，哪些需要语义判断或人工核查；失败时降级、继续或停止。
7. **数据与恢复**：来源保存范围、恢复、版本保留和隐私；避免把不必需的补查与版本对比当成当前发布阻塞项。
8. **模型和工具**：供应商、可替换性、超时、失败处理与成本，基于实际可用配置及评测决定。

对每一项采用统一记录：问题与证据 → 选项和取舍 → 用户决定 → 验收方式与限制 → 实施后实际结果。先写一个可审核的设计，再由用户确认重大决策后实施；本草案不构成对全部架构修改的预先授权。

## 7. 推进方式：方案设计、开发与评测并行

> 2026-10-29 用户决定：不把完成评测体系或跑公开 benchmark 当作开展整体方案设计和开发的前置条件；评测与设计、开发并行。重大设计决策仍由用户参与；每一步实施和必要验证依据已授权范围进行。

| 工作线 | 当前工作 | 并行的最小反馈 | 关键决策 |
|---|---|---|---|
| 产品与整体方案 | 在已定方向基础上，梳理输入、调查、证据、结果和页面的责任及失败语义；对照当前实现 | 用一两个具体场景检验设计是否回答用户需要；不要求先完成完整评测集 | 用户参与确认范围、完成标准及重大取舍 |
| 现状审计与小步开发 | 区分已实现、部分和待实现；优先解决影响真实主路径的问题 | 每项改动做必要的功能、恢复或链路验证；涉及外部调用时明确实验条件和成本 | 基于现状和失败证据，用户参与架构和主要机制选择 |
| 评测与坏例积累 | 复用现有冻结资产，逐步研究公开基准并积累针对任务的样例 | 同步记录问题、输入、输出、原因、模型和成本；逐步人工复核 | 样本分布、评分与阈值由用户参与决定；先观察基线 |
| 面试复盘 | 记录问题、选项、权衡、实际结果与已知限制 | 随设计和验证同步更新，不把设想当成已实现 | 用户主导理解和表述 |

公开 benchmark、完整评测平台和固定数量的人工标注案例均非当前整体设计工作的前置条件。已有“先标注案例、测出基线后共同确定量化阈值”的决定保留，但允许随开发并行推进；不因尚无量化阈值就忽视重要错误。当前设计、实现事实和目标方案始终分开记录。

## 8. 需要用户参与决定的问题

- **D1 结果交付（已决定）**：模型或工具错误导致调查提前停止时，若已有可核查内容，展示部分报告，明确写出因错误提前停止、停止原因和未完成内容。无可核查材料及取消场景的展示方式仍待决定。
- **D2 澄清交互（部分决定）**：少量搜索后仍有多个可能事件时暂停调查并请用户选择；用户未回答时保持等待，不自动选择事件。消歧搜索工具暂时不可用时说明失败并请用户补充信息，仍无法确认事件则等待，不把工具失败解释为事件不存在。搜索无结果及用户明确拒绝回答时如何处理仍待决定。
- **D3 报告证据（部分决定）**：每个重要事实或观点应显示来源链接和相关原文摘录，并标明是谁的说法。搜索摘要提到重要信息但无法读取原文时，不写成已核实事实，可列为待核查线索并注明原文无法访问。已读取的来源在之后链接失效时，允许查看保存的摘录，标明读取时间及原链接不可用；链接状态以检查时间为准，检查失败时标记无法确认。保存范围、检查时机和定位粒度仍待决定。
- **D4 评测规模与门槛（部分决定）**：由我们亲自标注一批案例，测出基线后共同决定量化门槛；基线不是合格证明。时间预算、案例数量、标注与复核分工及具体门槛仍待确定。
- **D5 既有能力处置**：旧补查、版本对比、多种页面和历史资产哪些保留；哪些只是暂不承诺而非删除。
- **D6 编排方案**：先测量和解释单 Agent，还是为明确失败引入其他工作流；没有评测前不预选。
- **D7 用户研究**：当下只做自主模拟，未来若有志愿者再评估可用性；不可把模拟反馈写成真实客户效果。

## 9. 面试表达边界

可以讨论最初合作背景与需求变化，但应如实说明合作已经结束、平台采集未解决，以及现阶段的对象是自行构建的公开网页调查系统。对个人参与部分，说明此前代码大量由 AI 辅助完成，后续由本人主导产品与设计决策并参与评测，具体声明以实际完成为准。任何准确率、业务效率、独立来源覆盖与可靠性结论都必须有对应样本、方法和证据，不能因技术名称或单次成功而推断。
