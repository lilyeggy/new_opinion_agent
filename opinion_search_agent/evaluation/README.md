# 质量门禁（offline quality gate）

把"检索召回 / 忠实性 / 零虚构"这三个对外引用的数字，从一次性人工统计变成**任何人可以离线重算**的检查。

```bash
# 重算并写回基线
python scripts/quality_gate.py

# 校验：任何数字漂移都会以退出码 1 失败
python scripts/quality_gate.py --check
```

不调用模型、不访问网络：输入全部是仓库里已经冻结的文件。

## 三个数字怎么来

### 1. 检索召回 6/10

`annotations/sanjiu-must-hit.json` 是人工写的 10 项"合格调查必须找到的内容"清单。每一项带一条机械 `match` 规则（`keywords` 命中标题任一，`domain_suffix` 命中域名），由门禁对运行的 **候选池**（发现层）和 **实际已读来源**（已读层）分别求交集。

- 已读层：6/10，与历史记录完全一致。
- 发现层：机械判定 7/10，历史记录 6/10。唯一分歧是第 7 项（大河网"河声"评论）：候选池里确实有一条 `news.qq.com` 转载，历史人工判定认为原发内容未被覆盖。门禁把这个分歧打印在 `baseline.md` 的"人机分歧"一节，人机一致率 9/10，而不是把规则调到"刚好等于 6"。

### 2. 忠实性 10/14

`annotations/sanjiu-faithfulness.json` 是对 s5-b 运行 14 条 finding 的逐条人工标注，按 `findings` 数组顺序给出 `claim_id` 与判定：

- 完全支持 = 文本里的事实、引语、归属都能在**绑定摘录**里找到；
- 部分支持 = 事实成立但摘录没有覆盖全部引语或归属（4 条：F3/F6/F10/F11，失败模式是"摘得不够"而不是"编"）；
- 无中生有 = 摘录完全不支持（0 条）。

门禁同时重算运行自己的 review verdict（supported 6/14），用来对照"系统自评比人工更严"。

### 3. 对抗埋点 2/3

`annotations/sanjiu-adversarial.json` 定义三篇手写埋点（7 篇真实快照 + 3 篇埋点一起做 sha256 冻结，真实模型跑生产回放链路）上的三个检查：

| 检查 | 结果 | 说明 |
| --- | --- | --- |
| 更正说明是否进入判断层 | 通过 | 更正事实成为报告唯一的"已核查阶段性判断" |
| 反方稿证据是否被引用 | **未通过** | 反方稿被读、被摘了 5 条证据，但没有一条判断引用它 |
| 被放大 10 倍的数字是否进入判断层 | 通过 | 判断层没有 `3160.3` / `908.9`，但它们确实以原始摘录出现在报告末尾的"来源与证据"附录里 |

最后一条是**诚实的通过**：它说明的是"这一轮没轮到综合"，不是"系统有数字校验收拦截"。附录里出现这两个数字这件事本身也被记进 `baseline.json`。

第四条是 2026-10-17 新增的**机制层**检查（`layer: mechanism`），它与前三条的报告层行为分开统计：

### 4. 数字矛盾检测（机制层）

`src/opinion_search/domain/numeric.py` 只回答一个问题：**同一个钱指标，是否在两个文档里出现了一个数量级之差**。

- 取数字前 18 字窗口当指标名，去掉年份、切掉"高达/达/为/约/超"这类词尾；
- 按最长公共后缀（至少 3 字）聚类，`公司销售费用` 与 `年销售费用` 会归到同一组；
- 只在**跨文档**、且比值四舍五入到整十次幂（容差 0.02）时报告。

把对抗案例的 10 篇冻结材料一起喂进去，报出 5 条冲突、覆盖 4 个指标（营业收入 316.03 vs 3160.3、销售费用 90.89 vs 900、归母净利润 34.21 vs 342.1、推广费 50 vs 501.9），两轮真实运行的证据集零误报。

它把"错误数字没传播"从**侥幸**（步数耗尽）变成**可复算的机制证据**，但**尚未接进运行时**——所以报告层仍然是 2/3，门禁也照实分开列这两行。

### 5. 引语溯源（引语级）

判断文本里的每个引号片段都要能在它绑定的摘录里找到；找不到时再分三种情况：

| 情况 | s5-b 计数 | 含义 |
| --- | --- | --- |
| `in_excerpt` | 16 | 引语就在绑定摘录里，逐字可核 |
| `recoverable` | 8 | 原文有、摘录没摘，确定性回填就能补上（不需要模型） |
| `absent_from_doc` | 1 | 已读原文里根本没有这句话 |
| `doc_unavailable` | 1 | 来源没有冻结快照，无法核 |

26 个引号片段的覆盖率是 61.5%，回填上限 92.3%。这条指标把 D4 的结论"失败模式是摘不是编"变成可重算的数字：8 条漏摘全部落在 `partial` 判定上，而唯一"原文里找不到"的引语出现在 `supported` 判定里。

运行时侧是 `src/opinion_search/investigation/quotes.py` 的确定性护栏：review 阶段若一句引语在该判断引用的来源原文里都找不到，程序直接把它降级为 `partial` 并写明原因，不依赖评审模型的自律。

同一套定位逻辑也用来**回填**：reflect 阶段 `Executor._record_findings` 把「原文有、摘录没摘」的引语定位出精确字符区间，写成 `Evidence`，再通过 `FindingEvidence` 绑回该判断的 `evidence_ids`。因此 92.3% 是运行时可达的上限，不只是纸面数字；只有「原文里根本没有」的那一类无法回填，会被护栏降级。这个上限尚未在真实运行上复测——复测需要重跑模型。

## 边界

- 门禁保证的是"给定这些冻结运行，数字可重算、可回归"，不保证标注本身正确，也不证明换一个模型或搜索引擎仍然成立。
- s5-b 的 11 个已读来源里有 4 个没有冻结快照，它们的 25 条证据标记为"不可核"，不计入引用可核率的分母。
- 两条 OpinionSearch 轻路径案例只覆盖 opinion 域（没有 findings / review 层），作用是冻结当日两次真实运行的回归指纹。
- 数字矛盾检测目前只是**离线机制证据**，尚未接进 `investigation` 运行时；它不改变任何一次真实运行的行为。
- 引语护栏只降级「原文里根本没有」的引语；「原文有、摘录没摘」的 8 条目前只被度量、没有被回填，所以 92.3% 是上限而不是现状。
